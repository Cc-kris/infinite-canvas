## 0.25.7 修复：更新内容空白、Agent 模型列表串台、选了 Claude/Galley 仍加载 Codex

这次一起处理四个反馈，本质是同一条线：Claude Code 与 Galley 两个运行时是后接的，只做通了「能跑一轮」，周边状态没跟 Codex 对齐。

1. **更新弹窗没有内容**。弹窗的更新条目只读仓库 `CHANGELOG.md`，而 0.25.x 这些版本只写进了桌面版发布说明，CHANGELOG 停更在 0.24.0，
   于是「有新版本」却一片空白。现在补上了 0.25.x 的记录；更关键的是加了兜底——CHANGELOG 里查不到当前版本时，
   直接取 GitHub Release 正文里的条目显示，以后漏写也不会再空。
2. **切到 Claude Code / Galley，模型列表还是 Codex 的**。模型清单请求只按「地址+令牌」缓存，运行时换了缓存不失效；
   Galley 侧原本直接返回空列表；再加上没有推理档位的模型会被整条丢掉，界面就干脆留下来上一套 Codex 模型。
   现在运行时一变就重取：Galley 直接读它自己的模型库（`galley llm list`），没有档位的模型给一个占位档而不是丢掉；
   运行时切换还会主动广播一次，前端收到就刷新。
3. **选了 Galley，新建会话还是加载 Codex 插件**。服务启动时有「活跃线程」就直接准备 Codex 线程，
   新建会话、恢复旧会话两条路由也无条件走 Codex，完全不看当前选的是哪个运行时——于是 Codex 的 app-server 与它的 MCP 插件又被拉起来。
   现在这三处都按运行时判断：Claude Code / Galley 下只切本地会话状态，不碰 Codex。
4. **与 Codex 的功能对等**：图片附件现在也把清单交给 Agent（之前选了图等于没选）；
   Galley 支持中断（发 `session stop`）；换模型会自动新建 Galley 会话（模型在会话创建时固定，否则选了不生效）；
   同一会话继续用 `session send` 续接，上下文能保住。

验证：两端 typecheck 与单测通过；隔离配置起服务实测——切到 Galley 后 `/agent/models` 返回 Galley 自己的模型，
新建/恢复会话都不再产生 Codex 子进程；真实跑三轮 Galley 对话，首轮回复正常、换模型自动换会话、同模型续接保持同一会话。

## 0.25.6 修复：切换 Agent 后一直「连接中」

现象：已经连着 Claude Code，再点 Codex（或反过来），界面一直转圈，卡片停在「未连接」、顶部写着「当前连接中」，
等多久都不恢复。0.25.5 加上互斥锁之后，至少按钮会被锁住不会再点乱，但「切换后连不上」这个根因这次才算修掉。

两个缺陷叠在一起：

1. **同步凭据时把已经建立的连接打回「连接中」**。连接面板会定期向主进程要一次连接信息，
   发现地址或令牌跟当前不同就同步过来；但这个同步走的是「重新连接」的入口，会无条件把状态重置成
   未连接 + 连接中。而切换 Agent 时主进程本来就会换发新令牌，于是刚连上的会话被自己重置掉。
   更麻烦的是定时探测的回调里读到的是旧的地址/令牌，判断永远成立，每 1.5 秒重置一次。
   现在同步只更新地址与令牌，不动连接状态；判断也改成读最新的凭据，不再被旧值误导。
2. **连接成功后又一次重置**。点「连接」后主进程返回地址与令牌，前端拿到结果会再同步一次，
   而那时事件流往往已经用同一套凭据连上了。凭据没变、事件流不会重建，状态却被打回「连接中」，
   界面就永久卡住。现在遇到「已经连接、凭据与当前完全一致」直接跳过，不再重置。

验证：三轮独立真机测试（worker 只读仓库、用 CDP 真实操作界面）——前两轮复现缺陷，
修复后 Claude ↔ Codex 来回切换各在 1.5～2.5 秒内到达「已连接」并连续保持 20 秒不变；
切换进行中三个 Agent 按钮全部禁用，绕开界面直接调连接接口会返回「正在连接 X，请等它结束再切换」。

## 0.25.5 修复：开着代理也「fetch failed / 生图请求超时」

现象：Windows 用户安装后生图失败，一次报 `fetch failed`，一次报「生图请求超时」；同一台机器上浏览器能正常打开同一个站点。

原因是本地代理的出站通道选错了。应用里所有 API 请求都先发到本机的 `127.0.0.1:23210`，再由它转发出去，而这一跳用的是 Node 自带的
`fetch`（undici）。**undici 不读 Windows 的「系统代理」设置，也不读 `HTTPS_PROXY` 环境变量**——所以只要用户是 Clash / V2Ray 的
「系统代理」模式（没开 TUN 虚拟网卡），应用里的请求其实是**直连**出网的：墙外接口就会表现为 DNS 解析失败（`fetch failed`），
或者连接建立了但数据永远不回来（干等 10 分钟后前端报「生图请求超时」）。自己是 TUN 模式、或用国内可直连中转的，看不出这个问题。

这一版把出站改成两条通道，按顺序试：

1. **系统代理通道**：Electron 的 `net.fetch`（Chromium 网络栈），跟随系统代理 / PAC，Clash 的「系统代理」模式对它有效；
2. **直连通道**：原来的 Node `fetch`，作为兜底。

第一条失败（DNS、连接被拒/被重置、代理没启动、握手超时）自动换第二条，两条都失败才报错。
上游如果用 `403` / `407` / `451` 明确拒绝这条出口（国内中转站常封境外 IP），也会自动改走直连——
这种情况下换路不会重复计费；`401` / `429` / `500` 属于接口自己的答复，不会重试。顺带两处：

- **错误不再是一句英文**：两条通道都失败时返回中文原因 + 处理建议，例如
  「无法连接 api.example.com：域名解析失败（ENOTFOUND）。建议：…请确认代理已启动，必要时切换为全局/TUN 模式；已尝试 系统代理:ERR_PROXY_CONNECTION_FAILED / 直连:ENOTFOUND」，
  代理没启动、DNS 不通、证书被中间人、接口地址填成了网页地址，各有一句对应的说明。
- **等待上游响应头有了上限**：180 秒（两条通道共享 1.5 倍总预算），黑洞地址不会再无限期挂着；响应头到手后不再计时，生图和流式输出照旧。
- 应用内「检查更新」和安装包下载也改用同一套出站，GitHub 打不开的网络环境下不再静默失败。

代理本身仍然只监听 `127.0.0.1`、不落盘、不碰 API Key，转发规则不变。



现象：Windows 上点「更新」，安装包下载完成，应用直接退出，之后既没有安装窗口也没有重新打开，像是被吞掉了。

原因有三层，都在这一版修掉了：

- **多余的一层 PowerShell 提权**：旧代码在非管理员时会先跑
  `powershell Start-Process -Verb RunAs`，再把 `/S /allusers --force-run /D=C:\Program Files\...` 当参数串传进去。
  PowerShell 会重新拼一遍引号，装到含空格的目录（Program Files 就是）时 `/D=` 会被拆坏；更要命的是
  UAC 被拒或 PowerShell 直接退出时，调用方 1.2 秒后照旧 `app.quit()` —— 用户看到的就是「退出了，没下文」。
  现在直接把安装器拉起来：electron-builder 的 assisted 安装器在静默升级「所有用户安装」时本来就会自己
  申请管理员权限，这层包装纯属帮倒忙。
- **安装范围参数写错**：`/allusers` / `/currentuser` 是安装器唯一认的写法（单斜杠）。
  旧代码传的是双横线 `--allusers`，被整条忽略，安装范围退回注册表推断。
- **失败没有出口**：安装器拉不起来时旧代码只在控制台打一行日志，然后照样退出应用。
  现在拉不起来会把错误抛回界面；下载完成的字节数和资产大小对不上（断流/代理截断）也会拦下来并提示。

顺手加的两个可观测性改进：

- 升级过程写日志到 `%APPDATA%\Infinite Canvas\update.log`（启动参数、字节数、安装器 pid、失败原因），
  下次再有异常可以直接看这个文件。
- **「更新没装成」会在下次启动时明确告知**：升级前落一个标记，重启后如果版本号没变，
  会弹出对话框说明「上次更新到 x.y.z 没有完成」，并给一个「打开下载页」的按钮，
  而不是让用户对着一个静默失败的应用自己猜。

## 0.25.3 新增：Claude Code 与 Galley 也能真正用起来

上一版只有 Codex 能完整使用：切到 Claude Code 或 Galley 后，连接虽然显示成功，但聊天区、技能页、
MCP 清单仍然是 Codex 的内容。这一版把「连接之后的每一步」都接到了当前运行时上：

- **聊天区文案跟随运行时**：输入框占位（询问 Claude Code / 询问 Galley）、模型与权限按钮的名字，
  都由当前运行时决定，不再写死 Codex。
- **MCP 清单真实化**：新增 `GET /agent/mcp` 接口。Claude Code 会实际执行 `claude mcp list`，
  把每个 MCP 服务的连接状态与失败原因带回界面（例如某个 MCP 未安装时直接给出 `ENOENT` 说明）；
  Galley 的 MCP 由桌面版自己托管，界面会明确说明「画布侧暂不可读」，而不是显示成一个空列表。
- **不再出现「0 个 MCP 服务已完成初始化」**：只有在确实拿到清单时，对话页才显示 MCP 汇总行。
- **技能页跟随运行时**：Galley 会提示「Galley 使用自己的技能目录，暂不支持在画布侧管理」，
  不再把 Codex 的技能列表铺给它。
- **Galley 没有画布侧模型选择**，模型按钮自动隐藏，不再留一个空下拉。

## macOS

- 下载 `Infinite-Canvas-<版本>-mac-arm64.dmg`（Apple 芯片）或 `-mac-x64.dmg`（Intel）。
- 打开 DMG，把 **Infinite Canvas** 拖进「应用程序」。
- 首次启动若提示「无法打开，因为无法验证开发者」，在「系统设置 → 隐私与安全性」点「仍要打开」；
  或用终端执行一次：

  ```bash
  xattr -cr "/Applications/Infinite Canvas.app"
  ```

## Windows

- 下载 `Infinite-Canvas-Setup-<版本>-x64.exe`。
- 运行安装包；SmartScreen 提示「Windows 已保护你的电脑」时点「更多信息 → 仍要运行」。
- 安装向导第二步可以**自选安装位置**（默认 `%LOCALAPPDATA%\Programs\Infinite Canvas`），也可改为按机器安装。

## 这一版有什么

- **本地 Agent 一键连接**：右侧 Agent 面板的「连接设置」变成三张卡 —— Claude Code、Codex、Galley，
  各自显示是否已安装、装的哪个版本。点「连接」即可，桌面端会在后台拉起内置的 agent 服务并完成握手，
  不用再手填地址和 token；原来的手动填写收进「高级」折叠里作兜底。
- 选中的运行时会记下来，重启后仍然生效；想换一个，直接在另一张卡上点「连接」。
- **三种运行时都是完整可用的状态（0.25.3）**：聊天占位、模型与权限按钮、技能页、MCP 清单都会跟着切换，
  切换后不需要重启应用。
- 顶部菜单栏的「编辑 / 视图 / 窗口」已移除，右上角的文档入口也一并去掉。
- 生图工作台与视频工作台的选中框改为橙色高亮，跟画布主题统一。
- **应用图标与界面 logo 统一（0.25.1 修正）**：安装包里的 macOS `.icns` 和 Windows `.ico` 都改成与界面同一张 v2 图，
  满幅绘制、去掉原先 10% 的内缩留白，Dock / 任务栏 / 开始菜单显示的就是画布顶部那个 logo。
- 打包版两处稳定性修复：内置 agent 不再把版本号读成 `0.0.0` 并误报「有新版本」；
  连接 Codex 时不再因为找不到入口模块而启动失败。
- 画布数据仍保存在本地（IndexedDB），WebDAV 同步、提示词库等功能与网页版一致。

> **Windows 用户注意（从 0.25.2 / 0.25.3 升级）**：如果你从 0.25.2 / 0.25.3 点应用内的「更新」升级，跑的是**旧版**的升级代码，
> 它仍然可能「下载完就退出、没有任何反应」。**这一次请直接下载 0.25.5 的安装包手动运行一遍**；
> 装上它之后，后续的自动更新才会走修好的流程。
