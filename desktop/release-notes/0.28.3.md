## 0.28.3 修好「配好的渠道、生图记录，重启后全没了」

mac 上确实有用户遇到过：渠道配好、图也生成过，第二天打开客户端，渠道空了、记录也没了，像被重置一样。

数据其实一条都没删 —— **是应用换了个「门牌号」去找它**。桌面版把界面挂在 `http://127.0.0.1:23211`，
浏览器按这个地址分区存放数据：渠道配置在 `localStorage`，画布、生成记录、资产在 `IndexedDB`。
旧版本在 23211 被占用时（常见原因是上一次的本地转发代理没退干净）会**悄悄**把界面挪到 23212，
地址一变，新地址下就是一个空库，于是看起来「全没了」；挪回 23211，原来的东西全在。

这一版把门牌号钉死，并让「被占用」不再无声无息：

+ **界面永远在 23211**：端口被别的程序占着，也不再自动换号；会弹窗说明「23211 被占用」，
  给出「重试 / 打开数据目录 / 退出」三个选择。
+ **本地代理不再抢占 23211**：代理只在 23210 与 23212~23221 之间找位置，需要时还可以退到 23240 之后，
  从根上避免「自家代理把自家界面挤走」。
+ **旧数据有提示**：如果检测到旧版本曾经漂移出去留下的数据目录，弹窗里会一并告诉你「那一层数据还在」，
  点「打开数据目录」就能自己看到。

已经遇到过的用户，数据通常还在旧地址对应的目录里，没有丢；新版本不会再制造新的漂移。
