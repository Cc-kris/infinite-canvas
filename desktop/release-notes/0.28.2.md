## 0.28.2 视频生成不再被一次「秒失败」打断

Windows 上点「开始生成」，有时两三秒就红字失败，报的是 Cloudflare 的英文原文：

> The origin web server returned an invalid or incomplete response to Cloudflare.

这是 Cloudflare 的 520/502 —— **上游中转自己抖了一下**，不是配置写错，也不是模型不可用。
问题出在我们这边：创建任务那一步没有任何重试，上游抖一次就把错误直接甩给用户。
（实测复现：同一 key、同一请求体并发发 5 条，其中 1 条当场回 `error code: 502`，其余 4 条正常。）

这一版做了四件事：

+ **创建/下载加退避重试**：408、425、429、500、502、503、504 与 Cloudflare 的 520~525，以及连接被掐，
  自动隔 0.8 秒、2 秒再试，最多 3 次。覆盖视频创建、成片下载、直链抓取与「HTTP 自定义视频协议」的提交。
+ **中转走 JSON 优先**：官方 OpenAI 之外的中转只解析 JSON，以前要先发一次注定 400 的 multipart、还要多等十几秒，
  现在直接发 JSON；multipart 只作兜底。
+ **轮询不再误判失败**：轮询途中遇到瞬时 5xx/断连，继续等，不把上游其实还在生成的任务判成失败——
  被判失败后再点一次，就会重复扣费。
+ **错误文案说人话**：重试 3 次仍失败时，前面加一句「上游网关抖动（自动重试 3 次仍失败），通常是中转/Cloudflare
  瞬时故障，稍后重试即可」，后面保留原始报错、域名路径与 HTTP 状态码，方便截图排查。

实测：本地假上游前两次返回 502、第三次成功 → 工作台点一次「开始生成」，自动重试后正常出片
（768×768 / 6.58 秒 / 794 KB，可播放）；真实中转（sub2api + MiniMax-H3）同样跑通，创建 10 秒内进「生成中」。
