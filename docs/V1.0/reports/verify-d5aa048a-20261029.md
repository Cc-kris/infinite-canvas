## 残留风险（非本提交回归，如实记录）

1. **接线层无自动化覆盖**：`image-text-edit.tsx:225` 的 `useEffect` 只在纯函数层被间接验证；`ingestResultMedia` 依赖 IndexedDB，bun 测试环境无 `fake-indexeddb`，故"挂回 → 抓字节 → 拿 storageKey"全程需真实浏览器才能断言。本轮按约束未做浏览器 E2E。
2. **`latest` 选取口径**：`latest` 取该工具最新一条含 image 结果的任务，并额外要求 `succeeded`。若用户在成功任务之后又跑了一条失败任务且带 image 结果，effect 会整体早退，老任务不会被自愈（漏修，非误挂）。该选取逻辑是既有代码，非本提交引入。
3. **上游地址过期**：挂回后 `ingestResultMedia` 抓取失败会写 `ingestError`，结果项仍有 `url`（面板判"有结果"），此时点下载会拿到真实 HTTP 错误而不是静默 0 字节——行为可接受，但用户看到的是"报错"而非"已恢复"。
4. **draft 的 url 未按 taskId 绑定**：`values.resultImageUrl` 是"最近一次成功"的地址，代码未记录它属于哪个 taskId。理论上存在把 A 任务地址挂到更老的 stripped 任务上的窗口，但因换源图即清空、且同工具同上游，实际触发面极窄；建议后续在草稿里带 `resultImageTaskId` 做硬绑定（本轮不改，避免超出"只修明确回归"的边界）。
