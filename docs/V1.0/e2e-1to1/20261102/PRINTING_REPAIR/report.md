## 功能核验（只读源码 + 既有证据）

- 适配器：`web/src/features/tools/adapters/printing-repair.ts:360` `run: (input, options) => useToolTaskStore.getState().runTool(input, options)`，走共享 TaskGateway → 真实 images/edits。
- 字段落点（`registry/index.ts:214` PRINTING_REPAIR fields，makeType 29）：`stampingFlowerSegUrl`（印花分割图）/ `stampingFlowerUrl`（印花原图）/ `imageUrl`（底图）/ `point`·`scale`·`rotate`（印花定位变换）/ `version` / `width`·`height` / `config`·`targetConfig`。
- 本地的分割与变换是真实计算：Step 2 会先做像素分割（「白=印花本体」），Step 3 印花层支持拖动/方向键微调/滚轮缩放；`PRINTING_REPAIR_SCALE/ROTATE/STRENGTH` 均有 clamp 边界。
- 禁用项核对：本地 Step 2「从本地上传」在 Step 1 未就绪时 disabled；`开始修复` 在缺图/缺印花分割时 disabled（实测 true），并列出 4 条具体阻塞原因（满足规格「不只弹通用错误」）。
- 真实上游证据（非本轮）：`evidence/real-acceptance/PRINTING_REPAIR/result.json` —— status VERIFIED；真实上游任务 succeeded（2026-10-28T15:52Z），分割图印花占比 96.5%；产物 `https://oss-us.dimenoss.com/.../1793202782_….png` 1024×1024、1153165 bytes、sha256 `6ce8e2aa312bfb7e879ecab915eac77c058f02d7f138ee3c6eee63bef3bab5c3`；「存资产」回执 `已存入资产库（zCnoGDyr）`；「发送画布」回执 `已发送画布（项目 60gWQnVc · 节点 image-17）`；crossChecks 确认画布内真实图片节点存在。
- 本轮未提交生成（0 算力），故「真实生成」以代码路径 + 引用证据判定 REAL_PROVIDER。

## 结论

三步语义（消除错误印花 / 导入正确印花 / 调整印花位置）与建议提示保留，比原站多做了真实的印花分割与定位画布。但布局有 2 个 P1（三栏顺序倒置、结果区不再是独立列），并新增了原站完全没有的「修复参数」区块（强度/版本/对比方式）与 4 条常驻告警（其中「上游返回成功但没有图片结果」在空态即出现，语义错误）。**不给 PASS**。
