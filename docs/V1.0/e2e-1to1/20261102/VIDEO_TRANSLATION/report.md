## 功能代码路径与禁用/缺失能力核对（重点）

- **翻译专用通道：不存在。**
  - 页面顶部常驻警示：「当前为 AI 视频重生成，非逐句翻译 / 口型对齐；真实翻译通道未接入」。
  - 证据链：`adapters/video-translation.ts:160-166` 注释明确「当前 provider 契约（`web/src/services/api/video.ts`）只发送 prompt + 参考媒体 + 少量全局参数，没有任何『口型同步』开关」；`checkVideoTranslationCapability(..., { lipSyncSupported = false })` 默认 `unsupported`。
  - 后果：源语言/目标语言**只写进提示词**，上游无 `language` 字段，不能保证换语言、换字幕、对齐口型。结果区标签直接叫「AI 重生成结果（未验证翻译）」。
- **口型同步：不可用且已阻断。** `lipSync` 默认 `true`（registry 默认值），但 `evidence.lipSync = unsupported` → `requirements` 里 `lipSync.required=true` → 进入 `blockers`，提示「当前视频模型没有口型同步能力声明…请关闭「口型同步」后重试」。而页面上的开关是 disabled 且 `aria-checked=false`（已强制关闭），因此**用户无法在本页开启口型同步**。
- 输出数量：`nativeOutputCount = 1`，选 2/3/4 触发阻断；选 1 解除。
- 禁用态：「从商品库选择」disabled；「立即生成」disabled（缺原视频）。
- 缺失能力汇总：①无原生翻译通道；②无 lipSync 参数；③无字幕级 bilingual 输出；④无逐句时间轴对齐。

## 结论

- 本工具**不能按「1:1 复刻」判定通过**：核心能力（翻译通道 + 口型同步）在本地明确未接入，且实现方选择「如实披露 + 阻断」而非伪装成功——这一点值得肯定，但功能上与原站不是同一能力。
- 交互与布局可用（滚动可达、控件有真实前后差异）；本轮未提交生成，功能判定 NOT_RUN，仅记录「通道缺失」这一确定事实。
- 若要 1:1，需接入带 `language` + `lipSync` 的上游协议，或产品明确降级为「AI 重生成」并同步调整导航命名。
