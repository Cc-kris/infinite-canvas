## 功能核验（只读源码 + 既有证据）

- 适配器：`web/src/features/tools/adapters/fix-color.ts:208` `run: (input, options) => useToolTaskStore.getState().runTool(input, options)`，走共享 TaskGateway → 真实 images/edits（provider 由用户模型配置决定）；蒙版是真实 canvas 像素导出 `rasterizeFixColorMask()`（含 inverted/autoExpand），非占位。
- 字段落点（`registry/index.ts:199` FIX_COLOR fields）：`fixColorSegUrl`（区域色）/ `fixColorUrl`（目标色）/ `imageUrl` / `imageSegUrl`（蒙版导出）/ `imageName` / `version`；`imageResultUrl` 仅成功后回填。本地 `composeFixColorFields()` 只下发上述字段，颜色经 `normalizeColorHex()` 规范化，非自由拼接。
- 校验：`validateFixColorInput()` 覆盖「无原图 / 空蒙版 / 颜色非 #RRGGBB(AA) / 区域色=目标色 / 未知版本 / 蒙版与原图尺寸不一致」；`validateFixColorSource()` 覆盖 mime、20MB、长边 8192、短边 64。
- 真实上游证据（非本轮）：`evidence/real-acceptance/FIX_COLOR/result.json` —— status PASS；两次真实提交（24s / 41s），产物 1024×752 / 1024×1024，`diffVsInput.meanAbsDiff 14.75、pixelsOver12Pct 17.8%` 判定为真实改图；`fix` 段记录了 1:1 尺寸缺陷已修复。
- 本轮未提交生成（0 算力），故「真实生成」以代码路径 + 引用证据判定 REAL_PROVIDER。
- 禁用项核对：本地 4 个「作品库/商品库」按钮 disabled 且带明确 title（非静默禁用）；无图无蒙版时 `立即生成` disabled（实测 true）。

## 结论

三步主干（Step 1 待修复图 / Step 2 颜色参考 / Step 3 进行AI修复）保留，但本地在原站零控件区域新增了**颜色取值、ΔE、色卡、修复版本、画布笔刷工具条**五大块自造内容，并把配置栏塞到 320px 导致 `立即生成` 掉出首屏；两个「作品库/商品库」入口全部 disabled。布局有 1 个 P0（三栏顺序错位）与 1 个 P0 级自造区块（颜色/版本）。**不给 PASS**。
