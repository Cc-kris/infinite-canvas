## 功能验收（只读源码）

- `web/src/features/tools/adapters/ai-outpainting.ts:1-14` 文件头：走共享 TaskGateway（`useToolTaskStore.runTool`）；「provider 成功但没有图片 → 判 failed(empty-result)，绝不补造结果；上游状态未知只标 unknown」；**已知集成缺口**：「gateway 的 `ProviderInvocation` 只有 `{prompt, references}`，没有 mask 通道。所以扩图蒙版以『第 2 张参考图 + `fields.maskUrl`』提交：蒙版 PNG 的白色区域 = 需要补全的新增画布，黑色 = 保持像素不变的原图区域。等 gateway 增加 mask 字段后，只需把 `buildOutpaintInput` 里的蒙版从 `references[1]` 挪到独立字段」。
- `:214` 输出字段 `imageExpandUrl` 注释「提交时为空占位，成功后由结果面板写回第一张结果地址」；`:312`「没有结果时留空，不填占位图」。
- `:225-236` `createTaskStoreRunPort()` → `useToolTaskStore.getState().runTool`。
- 本轮未提交生成 → 运行期产物未复核；蒙版通道缺口意味着扩图结果**可能不完全遵守保留区域**（源码自述，未实测验证）。

## 结论

控件的**语义集合**（默认尺寸、宽高、提示词、生成数量、立即生成、生成结果/优秀案例/历史）与原站对齐；但**页面骨架完全重排**（原站底部参数条 + 右侧结果栏，本地左参数卡 + 上下堆叠），并缺失原站最核心的「平台尺寸/比例扩图/自定义」三 tab 预设体系与缩放/重传/删除工具条，同时自造了「标准/高清/2K」「快照 hash」「解锁原图」等元素。**不判 PASS。**
