## 功能核验（只读源码 + 本地真实记录）

- 注册表：`web/src/features/tools/registry/index.ts:485-498`，`NEW_DESIGNER` / makeType 99 / layout `designer` / adapter **`designer-host`** / 字段 `designerId`、`imageUrl`、`isDesignerUse`、`onClose`、`onDone`、`open`。
- 适配器头注释（`new-designer.ts:1-12`）：`services/api/tools/gateway.ts#submit 对 designer-host 直接抛 adapter-not-executable`，上游也没有「设计器 → 生成」接口；因此本适配器**不经过 image/video 网关**，而是「画布文档 → 真实 Canvas 像素合成 → 真实资产入库（uploadToolAsset）→ onDone 回传资产」，`合成与入库都是可注入端口…任一环节失败都显式失败，不返回占位图、不伪造 assetId`。
- `:97-103` `DESIGNER_TASK_ENGINE = "designer-canvas-composite"`（记录真实执行方式而非伪造模型名）。
- 本地历史里的完成记录 `商品图设计器 dz-mvtdi8ha-d5xy3b：画布 1200×1200px，背景 #ffffff，共 2 … designer-canvas-composite · image · 1 个结果` 是这条本地合成的真实产物，不是 provider 回执。
- 既有测试：`new-designer.test.ts:374 describe("适配器执行链路（可注入端口，失败即失败）")`、`:566 工作区渲染（无网络、无假结果）`、`:626 任务持久化`。
- 判定：**LOCAL_PROCESSING**（真实本地 Canvas 合成 + 资产入库，零算力、无 provider）。

## 结论

原站「商品图设计器」有两级形态：`/draw/designer-home`（大拖拽区 + 示例拼贴 + 6 列模板瀑布流 + 类型/品类/版式筛选 + 多选删除）与 `/designer?id=…`（56px 图标 rail + 368px 字体面板 + 自由画布 + 368px 画布/背景属性 + 顶栏下载/另存模板/整图翻译/保存状态）。本地只做出「设计器宿主」：420/896/405 三栏、左栏仅 159px 高、无图标 rail、无字体样式库、无画布尺寸/平台预设、无缩放与悬浮工具条；首页被简化成 5 张纯色色块卡、无筛选无多选。功能层是真实的本地 Canvas 合成（`designer-canvas-composite`），并有本地真实完成记录，符合 `designer-host` 无 provider 的事实。**视觉 FAIL / 布局 FAIL / 交互 PASS / 功能 LOCAL_PROCESSING**。
