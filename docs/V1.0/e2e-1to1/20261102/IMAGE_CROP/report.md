## 功能核验（本轮已真实执行）

- `web/src/features/tools/adapters/image-crop.ts:35` `IMAGE_CROP_ENGINE = "in-process-crop"`；`cropImage` 真实 canvas 绘制（旋转/翻转 → 取框 → 缩放到目标尺寸 → `canvas.toBlob`），零上游请求、零算力。
- 本轮实测：上传 `product.jpg`(1024×744) → 选「亚马逊 1600×1600」→ 点「开始裁剪」 → 任务完成，历史行写入「图片裁剪｜亚马逊 1600×1600｜裁剪框 140,0,744,744｜源图 product.jpg｜配置 a…」，`撤销` 由 disabled→可用，`下载图片` 可用。
- 既有取证（更完整）：`evidence/real-acceptance/IMAGE_CROP/result.json` —— 产物 205951 bytes、1024×744、sha256 `c046374eac48b82e5a7a76c1ff8c151a9fee60e3257ffe5d10a8912eecaeb708`，下载/存资产/发画布三动作均通过，录得 issue「刷新后裁剪结果不回流，且无历史列表 UI」——本轮实测该 issue 已改善（历史列表已存在），但结果本身刷新后仍不自动回流。
- 判定：**LOCAL_PROCESSING**（真实本地像素处理，非 provider）。

## 结论

裁剪能力真实可用且本轮已跑通一次端到端裁剪（本地处理，零成本）。但**首屏布局与原站差距最大的是工具条（通栏 → 右上角小段）、上传卡（居中卡 → 左下按钮）、平台预设（单列带图标可滚动列表 → 3 列截断网格）、比例 Tab（带文字说明 → 无文字方块）、搜索框缺失、目标尺寸默认 1×1 vs 1024×1024**。**FAIL**。
