# Local Development

This branch ships the desktop client only. The renderer (`web/`) holds UI and state; all business work runs in the main-process app service (`desktop/service/`, `127.0.0.1:23212`), and the renderer receives its address and per-launch token through the preload bridge. Running `web/` alone no longer works because there is no local service behind it.

## Prerequisites

- Node.js 20+ and pnpm
- macOS or Windows (Electron shell)

## Build and start the desktop app

```bash
pnpm --dir web install
pnpm --dir desktop install
pnpm --dir web build      # the main process serves web/dist
pnpm --dir desktop start
```

The window loads the built renderer from `http://127.0.0.1:23211`; the app service starts on `http://127.0.0.1:23212`. If a port is taken, each server scans up to 12 subsequent ports. In development the main process imports `desktop/service/index.mjs` directly, so `build:service` is only needed before packaging.

There is no renderer hot reload: after changing `web/`, run `pnpm --dir web build` and restart the app.

## Check the service

```bash
curl http://127.0.0.1:23212/health
```

`/health` needs no token. `/api/*` and `/files/*` require the token generated at launch and are only reachable from the renderer origin; other origins get `403`.

## Package installers

```bash
pnpm --dir desktop build:service   # bundles service.mjs and copies native ffmpeg
pnpm --dir desktop dist:mac        # or dist:win
```

`dist:*` already runs the Agent, service and renderer builds. Only the host architecture's ffmpeg is bundled, so build each target on matching hardware/CI.

## Data and logs

Runtime data lives under `<userData>/data/` (macOS: `~/Library/Application Support/Infinite Canvas/data`), with `state/`, `media/`, `media-index.json`, `logs/`, `plugins/` and `published/`. A one-time import of the old IndexedDB data runs on first launch and leaves `backup-indexeddb-<timestamp>.json` plus a `.migrated` marker. Old browser data is never deleted.

## Start the documentation site

```bash
cd docs
bun run dev
```

Common locations:

- Renderer pages and interactions: `web/`
- Main-process capabilities: `desktop/service/`
- Renderer-side service client: `web/src/services/api/desktop/`
- Documentation content: `docs/content/docs/`
